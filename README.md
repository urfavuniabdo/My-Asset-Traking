# نظام إدارة وتتبع الأصول والدعم الفني
### Asset Tracking & Technical Support System (ATS)

نظام متكامل لإدارة الأصول الثابتة، العهد الشخصية، الصيانة الوقائية، تذاكر الدعم الفني،
الجرد الدوري والتقارير — مبني بـ **ASP.NET Core 8** بواجهة عربية كاملة (RTL) للبيئة المصرية.

---

## 🚀 التشغيل السريع

```powershell
cd AssetTracking
.\run-local.ps1          # Windows
./run-local.sh           # Linux / macOS
```

يعمل بقاعدة **SQLite** — لا يحتاج SQL Server ولا IIS. المطلوب الوحيد
**.NET 8 SDK**. القاعدة والبيانات التجريبية تُنشأ تلقائياً.

**الدخول:** `delta.manager@ats.eg` / `Admin@123`
التفاصيل الكاملة في **[`AssetTracking/التشغيل-المحلي.md`](AssetTracking/التشغيل-المحلي.md)**

> **رأيت نسخة قديمة بعد `git pull`؟** مجلدات `bin/` و`obj/` مُستثناة في
> `.gitignore` فلا يحدّثها السحب. نفّذ `.\run-local.ps1 -Clean` ثم
> `Ctrl+Shift+R` في المتصفح.

### السياسات (Policies)
`AdminOnly` · `ManagerOrAdmin` · `TechnicianOrAbove` · `AuthenticatedUser`

### الحواجز الأمنية المُطبَّقة والمُختبَرة

- **عزل الشركات على مستوى قاعدة البيانات** — فلتر عام (Global Query Filter) على كل كيان
  يحقّق `ICompanyOwned`، فلا يمكن لمدير شركة رؤية بيانات شركة أخرى مهما كان الاستعلام.
- **عزل يدوي للمستخدمين** — `ApplicationUser` لا يحقّق `ICompanyOwned`، لذا يُفلتر
  يدوياً عبر `AdminController.ScopedUsers()`.
- **مقاومة IDOR** — أي محاولة وصول لسجل خارج نطاق الشركة تُرجع صياغة
  "غير موجود" (`NotFoundOrForbidden()`) ولا تُرجع 403 مطلقاً، حتى لا يُستنتج وجود السجل.
- **التزامن المتفائل (Optimistic Concurrency)** — `RowVersion` على `Asset` و `MaintenanceTicket`.
- **قفل الحساب** — 5 محاولات فاشلة ⇒ قفل 15 دقيقة.
- **منع رفع الصلاحيات** — مدير الشركة لا يستطيع إنشاء/ترقية مستخدم لدور `Admin`.
- **منع تعطيل الحساب الشخصي**.
- **سجل تدقيق غير قابل للتعديل أو الحذف** — يُكتب من داخل النظام فقط.
- **حماية CSRF** — `__RequestVerificationToken` على كل عمليات POST.

### شجرة التصنيفات (رئيسي ← فرعي)

`Category` كيان شجري عبر `ParentCategoryId`. البيانات التجريبية تُنشئ لكل شركة
**٦ تصنيفات رئيسية** و**٢٣ تصنيفاً فرعياً** (٢٩ لكل شركة، ١١٦ إجمالاً):

| التصنيف الرئيسي | التصنيفات الفرعية |
|---|---|
| أجهزة حاسب ولاب توب | لاب توب · حاسب مكتبي · شاشة عرض · تابلت |
| طابعات وماسحات | طابعة ليزر · طابعة حبر · ماسح ضوئي · آلة تصوير |
| أجهزة شبكات | سويتش · راوتر · نقطة وصول لاسلكية · جدار حماية |
| أثاث مكتبي | مكتب · كرسي · خزانة ملفات · طاولة اجتماعات |
| مركبات ومعدات نقل | سيارة ركوب · سيارة نقل · دراجة بخارية |
| معدات وآلات | مكيف هواء · مولد كهرباء · مصعد · معدات ورش |

**قواعد الشجرة:**
- الأصل يُربَط دائماً بـ**ورقة الشجرة** (تصنيف فرعي)، لا بالتصنيف الرئيسي.
  إن كان الرئيسي بلا فروع فهو نفسه يصبح تصنيف الأصل.
- الفرع يورّث `UsefulLifeYears` و`SalvageRate` و`DepreciationMethod` من أبيه
  افتراضياً، ويمكن تعديلها من `Admin/CategoryForm`.
- نموذج الأصل يعرض **قائمتين مترابطتين**: «التصنيف الرئيسي» ثم «التصنيف
  الفرعي» الذي يُبنى في المتصفح من `data-parent` على كل خيار.
- عمق الشجرة المستخدم حالياً مستويان. الكيان يسمح بأعمق، لكن نموذج الأصل
  يفترض مستويين فقط.

### ⚠️ عزل الشركة في القوائم المنسدلة — فلتر EF لا يكفي لمدير النظام

`GetIgnoreCompanyFilter()` يُعطِّل فلتر العزل العام لمدير النظام (`IsAdmin`)
حتى يستطيع إدارة كل الشركات. النتيجة الجانبية: أي قائمة منسدلة تُحمَّل بلا
تصفية صريحة تعرض له عناصر **الشركات الأربع مجتمعة** — أي كل اسم أربع مرات
بلا أي تمييز بينها.

لذلك كل عنصر في `LookupItem` يحمل `CompanyId`، وتُصفّى القائمة في المتصفح
حسب الشركة المختارة:

```csharp
// AssetsController.FillFormLookupsAsync
.Select(c => new LookupItem {
    Id = c.Id, Name = c.NameAr,
    ParentId = c.ParentCategoryId,   // للربط الشجري
    CompanyId = c.CompanyId          // للتصفية حسب الشركة
})
```

- **مدير الشركة**: فلتر EF يكفي — يرى تصنيفات شركته فقط.
- **مدير النظام في شاشة الإضافة**: تُحجَب كل القوائم حتى يختار الشركة،
  وتُعاد تصفيتها عند كل تغيير لها.
- **حاجز الخادم**: التحقق يقارن `CompanyId` صراحةً، فتمرير تصنيف من شركة
  أخرى يُرفَض برسالة «التصنيف غير صحيح.» — لأن فلتر العزل معطَّل للمدير،
  فبدون هذه المقارنة يقبل الخادم المعرّف الغريب.
- **ملاحظة**: `[Required]` على `int` غير القابل لـnull لا يمنع القيمة `0`،
  فيُتحقَّق من `CategoryId <= 0` صراحةً.

### تسلسل الأكواد
```
الأصول   : AST-YYYY-NNNNN     مثال: AST-2026-00042
التذاكر  : TKT-YYYY-NNNNN     مثال: TKT-2026-00021
الجرد    : AUD-YYYY-NNNNN     مثال: AUD-2026-00006
```

### قيم الـ Enums — **تبدأ من 1 وليس من 0**
```csharp
DepreciationMethod { StraightLine = 1, DecliningBalance = 2 }
LocationType       { Office=1, Factory=2, Warehouse=3, Building=4, Apartment=5, Branch=6, Other=7 }
AuditStatus        { Draft=1, InProgress=2, Completed=3, Cancelled=4 }
```
> إرسال القيمة `0` لأي منها يُنتج خطأ تحقّق: `The value '0' is invalid.`

### حساب الإهلاك
```
القسط السنوي (القسط الثابت) = (قيمة الشراء − القيمة التخريدية) ÷ العمر الإنتاجي
```

## سجل أعطال ماكينات المصنع (Machine Breakdown Log)

النظام يسجّل **الأعمدة الأربعة عشر** لسجل أعطال المصنع الورقي. الجدول يوضّح
مقابل كل عمود مكانه في النظام:

| # | عمود السجل | الحقل في النظام |
|---|---|---|
| 1 | Ticket ID | `TicketNumber` — يُولَّد تلقائياً `TKT-YYYY-NNNNN` |
| 2 | Date & Time | `ReportedAt` (+ `ResolvedAt` و`ClosedAt`) |
| 3 | Engineer Name | `RequestedByUserId` / `AssignedTechnicianId` |
| 4 | Production Line / Area | `ProductionLineId` → موقع بنوع `ProductionLine` |
| 5 | Machine / Station | `AssetId` → الماكينة أصل في النظام |
| 6 | Issue Category | `Category` (`IssueCategory`) |
| 7 | Problem Description | `Title` + `Description` |
| 8 | Root Cause Analysis | `RootCause` |
| 9 | Corrective Action | `Resolution` |
| 10 | Solved By | `SolvedByRole` (`SolvedBy`) |
| 11 | Technician Name | `AssignedTechnicianId` |
| 12 | **Downtime (Mins)** | **`DowntimeMinutes` — محسوب تلقائياً** |
| 13 | Status | `TicketStatus` |
| 14 | Photos Link | `PhotosReference` + مرفقات بـ`PhotoStage` (قبل/بعد) |

### ⚠️ زمن التوقف يُحسب تلقائياً — ولا يُدخَل رقماً

المستخدم لا يكتب «45 دقيقة». يسجّل **لحظتين** فقط:

```csharp
// MaintenanceTicket.RecalculateDowntime()
if (StoppedAt.HasValue && RestartedAt.HasValue && RestartedAt > StoppedAt)
{
    DowntimeMinutes = (int)Math.Round((RestartedAt.Value - StoppedAt.Value).TotalMinutes);
    CausedProductionStop = true;
}
```

| الحقل | المعنى |
|---|---|
| `StoppedAt` | لحظة توقف الماكينة فعلاً — تُسجَّل عند فتح التذكرة |
| `RestartedAt` | لحظة استئناف الإنتاج — تُسجَّل عند تسجيل الحل |
| `DowntimeMinutes` | الفرق بالدقائق، **مخزَّن** في عمود ليُجمَع ويُفرَز في التقارير |
| `CurrentDowntimeMinutes` | محسوب لحظياً — يشمل التوقف الجاري الآن |

**لماذا لا نستخدم `ResolvedAt − ReportedAt`؟** لأنهما لا يساويان زمن التوقف:
التذكرة قد تُفتح بعد توقف الماكينة بساعة، أو تُغلق إداريّاً بعد استئناف
الإنتاج فعلاً. الطابعان الزمنيان يقيسان توقف **الإنتاج**، لا عمر التذكرة.

**تحقّقات الخادم:** `RestartedAt > StoppedAt`، ولا استئناف بلا توقف، ولا وقت
في المستقبل. شاشة الحل تعرض الناتج **لحظياً بالـJS** بنفس معادلة الخادم،
لكن القيمة المعتمدة تُحسب دائماً في الخادم.

### مؤشرات KPI في قائمة التذاكر
- **ماكينات متوقفة الآن** — توقف مسجَّل بلا استئناف (نطاق `?scope=down`)
- **إجمالي زمن التوقف** — مجموع دقائق النتائج المفلترة
- فلاتر **فئة العطل** و**خط الإنتاج**، وفرز `?sort=downtime`

## مفاتيح تشغيل الوحدات (Feature Flags)

تسمح هذه المفاتيح بتسليم النظام لعميل يحتاج **إدارة الأصول والعهد والجرد** فقط،
دون أن يرى أي أثر للوحدات التي لا تخصّه. تُضبط في قسم `Features` بملف
`appsettings.json`:

```jsonc
"Features": {
  "Tickets": true,                // تذاكر الصيانة + SLA + سجل أعطال الماكينات
  "PreventiveMaintenance": false, // خطط الصيانة الوقائية الدورية
  "Financials": true,             // القيم المالية والإهلاك
  "ScheduledJobs": false,         // لوحة Hangfire ‎/jobs‎ والمهام المجدولة
  "InventoryAudits": true,        // جلسات الجرد بالمسح
  "Reports": true                 // التقارير + تصدير XLSX
}
```

> القيم أعلاه هي **الوضع الافتراضي الحالي**: التذاكر والوحدة المالية والجرد
> والتقارير **مُفعّلة** (لدعم سجل أعطال المصنع)، والصيانة الوقائية والمهام
> المجدولة **مُخفاة**.
> لإعادة تشغيل أي وحدة: اضبط مفتاحها على `true` ثم أعد تشغيل التطبيق
> (المفاتيح تُقرأ عبر `IOptions<FeatureFlags>` عند بدء التشغيل).

### طبقات الإخفاء الثلاث

إخفاء وحدة ليس مجرد إزالة رابط — يُطبَّق على ثلاث طبقات متكاملة:

| # | الطبقة | التنفيذ | الأثر |
|---|---|---|---|
| 1 | **التنقّل** | `Views/Shared/_Layout.cshtml` | يختفي رابط الوحدة من الشريط الجانبي |
| 2 | **المسارات** | `Filters/FeatureGateAttribute.cs` | أي طلب مباشر للمسار يُرفض من الخادم: إعادة توجيه للرئيسية مع رسالة، أو `404` لطلبات AJAX |
| 3 | **البطاقات والمؤشرات والأعمدة** | `HomeController` + الـViews | تختفي البطاقات والرسوم والأعمدة والأزرار من لوحة المعلومات وشاشات الأصول والعهد والإدارة، ولا تُنفَّذ استعلاماتها في قاعدة البيانات أصلاً |

الشاشات المُحكَمة على الطبقة الثالثة:
`Home/Index`, `Assets/Index`, `Assets/Details`, `Assets/Form`,
`Custody/MyCustody`, `Admin/CategoryForm`, `Admin/Categories`, `Reports/Index`.

المتغيّر `F` متاح في **أي** view مباشرةً لأن `Views/_ViewImports.cshtml` يحقن
الإعدادات عالمياً:

```cshtml
@{ var F = FeatureOptions.Value; }
@if (F.Financials) { <th>قيمة الشراء</th> }
```

### ⚠️ قاعدة إلزامية: الوحدة المُخفاة لا يجوز أن تمسح البيانات المخزّنة

عند إخفاء حقل من نموذج، لا يُرسله المتصفح في جسم الطلب ⇒ يُعطي رابط النموذج
(`Model Binder`) القيمة `null` ⇒ أي إسناد ساذج مثل `entity.X = vm.X` **يمسح
القيمة المحفوظة فعلاً في قاعدة البيانات بصمت** عند كل حفظ.

لذلك تُحاط الإسنادات بنفس المفتاح في الـControllers:

```csharp
// AssetsController.Edit
// ⚠️ الوحدة المالية مُخفاة ⇒ حقولها لا تُرسل مع النموذج. لو أسندناها
// من الـvm لمُسحت القيم المخزّنة فعلاً عند أي حفظ — لذا نتركها كما هي.
if (_f.Financials)
{
    a.PurchaseValue      = vm.PurchaseValue;
    a.SalvageValue       = vm.SalvageValue;
    a.UsefulLifeYears    = vm.UsefulLifeYears;
    a.DepreciationMethod = vm.DepreciationMethod;
}
```

نفس الحماية مُطبَّقة في `AssetsController.Create` و`AdminController.MapCategory`
(إعدادات الإهلاك الافتراضية للتصنيفات). **أي حقل جديد تُخفيه بمفتاح تشغيل يجب
أن يحصل على نفس الحماية.**

### ملاحظات تصميمية

- **بيانات الجرد تبقى ظاهرة**: عند إخفاء الوحدة المالية يظل **تاريخ الشراء ورقم
  الفاتورة** ظاهرين في شاشة الأصل ونموذجه، لأنهما بيانات جرد لا بيانات مالية.
  تختفي فقط القيم والإهلاك.
- **لا لوحة فارغة**: عند إخفاء التذاكر تصبح لوحة الفني بلا محتوى، فتُعرَض له
  بدلاً منها بطاقات: *عهدي*، *بانتظار موافقتك*، *مسح أصل*، *الجرد الدوري*.
- **الرسوم تتمدّد**: أعمدة الرسوم تتحوّل من `col-lg-4` إلى `col-lg-6` تلقائياً
  عند إخفاء رسم التذاكر، فلا تبقى فراغات في التخطيط.
- **لا استعلامات مهدورة**: استعلامات الوحدات المُخفاة لا تُنفَّذ على قاعدة
  البيانات إطلاقاً، وليست مجرد مخفيّة في العرض.
